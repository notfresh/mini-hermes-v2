# README 开源项目名片设计

## 目标

将 README 从“模块说明和使用记录”提升为面向开源主页、面试展示和项目评审的项目名片。读者在首屏应能回答三个问题：这是什么、为什么值得看、如何立刻运行。

## 目标读者

主要面向希望快速理解项目价值和工程判断的读者，包括面试官、开源浏览者以及准备进一步阅读源码的开发者。内容仍需让实际使用者能够沿着 Quick Start 启动项目。

## 信息架构

1. 项目标题和一句定位明确的 tagline，突出“可运行、可阅读、可扩展”的教学级 Agent 框架属性。
2. 能力标签，展示 Python 版本、OpenAI-compatible、Tool Calling、Skills、REPL / Plan Mode 等已有能力。
3. Quick Start，将安装、环境变量、最短运行命令提前并压缩为 30 秒路径。
4. 请求生命周期，用一段核心循环或流程图解释一次请求如何经过 LLM、工具执行和消息回填。
5. 五模块职责表，保留当前架构对照，但改用更易扫描的职责语言。
6. 可探索能力，集中介绍 Skills framework、Plan Mode、agent-ignore 等已经存在的扩展点。
7. 工程边界，明确项目适合学习、拆解和实验，不宣称生产级可靠性。
8. 传承关系和路线图，保留 V1、V2、Hermes 的关系以及未来扩展方向。

## 内容约束

- 只描述仓库中已经存在或 README 当前已经承诺的能力，不虚构安装方式、命令或接口。
- 中文作为主叙事语言，代码、命令、路径和模块名保持原样。
- 保留现有可执行示例，优先调整顺序、措辞和分组，不做无关代码修改。
- 第一屏避免堆叠实现细节；架构表、设计来源和扩展方向放在读者建立定位之后。
- 明确 DeepSeek 优先和 OpenAI 兼容客户端的实际使用前提，并提示 API key 配置。

## 验证标准

- README 中的所有命令、文件路径和模块名都能在仓库中找到对应依据。
- Quick Start 能让新读者从依赖安装到首次运行获得清晰路径。
- 首屏能独立表达项目定位，不依赖阅读后续章节才能理解。
- Markdown 标题层级、代码围栏、链接和表格格式正确。
- 不改变 Python 源码、依赖或运行行为。

## 不在本次范围

- 不修改 CLI、模块实现、依赖版本或测试。
- 不新增徽章、外部图片或无法验证的性能数据。
- 不把 README 改写成完整教程，也不补写路线图中尚未实现的功能。
